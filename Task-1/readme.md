# Task 1 – Automated S3 Bucket Cleanup (Objects Older Than 30 Days)

## Task Description

Amazon S3 buckets are often used to store backups, logs, application assets, and temporary files. Over time, these objects can accumulate and unnecessarily increase storage costs. This task automates the cleanup process by identifying and deleting objects that are older than a specified retention period.

For demonstration purposes, the retention period was temporarily reduced to **1 minute** during testing. In a production environment, the retention period should be configured to **30 days** as specified in the assignment.

---

# Objectives

- Automate deletion of stale objects stored in an Amazon S3 bucket.
- Use AWS Lambda with the Boto3 SDK to perform the cleanup.
- Follow the principle of least privilege by creating a custom IAM Role and Policy.
- Print the names of deleted objects in the Lambda execution logs.
- Verify the successful execution using Lambda Test Results.
- Demonstrate how the solution can be scheduled using Amazon EventBridge in a production environment.

# Step 3 – Create the IAM Policy

Attach a custom inline policy to the role created in the previous step.

The policy file is available in this repository.

```
Task-1/LambdaS3CleanupPolicy.json

```

### Permissions Included

| Permission | Purpose |
|------------|----------|
| s3:ListBucket | Allows Lambda to retrieve the list of objects stored inside the bucket. |
| s3:DeleteObject | Allows Lambda to delete objects that satisfy the retention condition. |
| logs:CreateLogGroup | Creates a CloudWatch Log Group during the first execution. |
| logs:CreateLogStream | Creates a log stream for each Lambda execution. |
| logs:PutLogEvents | Writes execution logs generated by the Lambda function. |

### Role of the IAM Policy

The IAM Policy grants the Lambda function only the minimum permissions required to perform the cleanup operation. Following the Principle of Least Privilege ensures that the function cannot accidentally modify other AWS resources.

The Lambda function will perform the following operations:

- Connect to Amazon S3.
- Retrieve all objects stored inside the bucket.
- Compare each object's LastModified timestamp with the configured retention period.
- Delete objects older than the configured threshold.
- Print the deleted object names in the execution logs.

A successful execution returns a response similar to:

```json
{
  "statusCode": 200,
  "body": "Cleanup completed successfully."
}
```

# EventBridge Automation

Although EventBridge scheduling was not demonstrated in this implementation, the Lambda function is designed to support automated execution using Amazon EventBridge.

In a production environment, an EventBridge Rule can be configured to invoke the Lambda function automatically at scheduled intervals (for example, once every day) to ensure continuous cleanup of outdated objects without manual intervention.

---

# Discussion

Amazon S3 provides Lifecycle Rules as a fully managed solution for deleting old objects without requiring custom code.

However, AWS Lambda is preferred when more advanced cleanup logic is required, such as:

- Deleting files based on naming conventions.
- Performing conditional deletion.
- Sending notifications before deleting objects.
- Integrating the cleanup process with other AWS services.

Therefore, Lambda offers greater flexibility when custom business logic is required beyond standard lifecycle policies.
